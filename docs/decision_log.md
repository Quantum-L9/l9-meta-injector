| 41 | A corpus has two identities, a hash says how it was obtained, and a missing drive stays visible | [ADR-041](decisions/041-corpus-source-identity-verification-class-and-partial-corpora.md) | Source identity excludes every analysis profile and analysis identity binds them all, so changing a model or a threshold no longer reports that the disks were rewritten; each root emits its own Repository Model Packet under `roots/<root>/bundle/` and its packet id participates in the source snapshot; cached interpretations carry no subject and are rebound per root, closing a defect where one root's artifacts absorbed another's documents; `--incremental` may carry a prior hash forward and the snapshot is then `cached_unchanged_assumption`, never `fully_verified`, with `--verify-content` restoring one; `--allow-partial-roots` records a missing drive in the snapshot and labels the corpus partial rather than dropping it; readiness metrics are grouped with their denominators and separate three kinds of not-knowing. |
| 42 | Documents are decoded, work is bounded, and evidence is bound to what it describes | [ADR-042](decisions/042-binary-document-decoding-generational-publication-and-bounded-candidate-work.md) | Closes ADR-040's text-only scope amendment: seven decoders for PDF, OOXML, notebooks, CSV and HTML with no new runtime dependency, each block citing its own format's coordinate and no format without lines given a line number. Diff counts are computed from a snapshot analysis manifest or reported `null` with a reason, never zero. Worker budgets are implemented or removed and a retired flag is refused by name. Topic candidates run at ten thousand documents under an exact rarest-first prefix bound — 47,428,930 exhaustive pairs, 9,733 evaluated — held to an exhaustive reference at six thresholds. Outputs publish into `generations/<id>/` behind one atomic `CURRENT.json` switch, cache and session writes fsync file then parent, roots declare whether their identity was declared or inferred, a real archive is scanned only when an operator names one, the topology harness proves it wrote nothing into the consumer checkout, and the validation report is bound to a digest of the tree it ran over. |
| 43 | A decoded document's statements are read, and cited where they were made | [ADR-043](decisions/043-document-statements-are-read-and-cited-where-they-were-made.md) | Completes ADR-042, which decoded seven document formats into blocks and then reported every one of them as having said nothing: `interpreted_count` was structurally zero for any format without lines, so an operator's report showed statuses, tasks and blockers read out of the Markdown in an archive and out of none of the Word documents, decks or spreadsheets beside it. The work-intelligence recognizers now return a position-free reading and two callers attach the coordinate their own source has — a line span for a file with lines, a block id and structured locator for one without — so one implementation decides what a status declaration is and a `.docx` plan cannot disagree with the `.md` copy of it. Block-bound evidence is its own type and reaches readiness, the semantic passes, coverage, the corpus index and the report, and deliberately not the Repository Model Packet, whose evidence is a line span; Topology is unchanged and no dispatch is made. Three defects found while closing it: the document index stamped one decoder on every row and derived `normalized_document_id` from it, so the index, the cache and every piece of evidence were joined by a key computed from a decoder that had not run; an incremental scan dropped the `unsupported_encoding` observation a full scan recorded, moving the packet semantic hash and the corpus source snapshot id for an untouched disk holding one non-UTF-8 file; and the CSV decoder's smallest unit was the row, so a register with a status column was understood only when the identical table was a worksheet. `l9.document-index/v2`, `l9.document-coverage/v2` and `l9.document-signals/v1` correct what their predecessors said rather than adding to it, and `corpus-report.md` states exact observation, per-format decoding with eligible beside decoded beside understood, intelligence and embedding, so "we looked and found nothing" and "we could not read this" are two rows rather than one number. |
| 44 | One ZIP authority, two output modes, and a cache key that names the policy it answered | [ADR-044](decisions/044-unified-archive-reading-and-materialization-boundary.md) | Closes an audit that found two engines deciding what a ZIP is and several places deciding whether a file had changed. `localFiles` loses its independent `unzip` parser and extractor and consumes the canonical reader, preflight and policy, keeping its sibling `.l9extracted` materialization because that output mode is the opted-in feature rather than the duplication. Archive cache identity becomes the archive bytes, the reader version and a fingerprint over the fully resolved policy: the version string cannot express a value change, so two policies both declaring version `1` while permitting ratios of 200 and 10 had been sharing a verdict, and the fingerprint is statically required so a key without one cannot be constructed. One nanosecond-aware comparator replaces three millisecond-only checks that could disagree about the same file. An archive whose staged bytes contradict the digest the snapshot recorded is held with no member claimed and the observation becomes unstable. A scratch parent resolving inside the observed source, directly or through a symlink, is refused before any directory is created. Deflate's bounded whole-member buffering is documented as what it is rather than redesigned. |
