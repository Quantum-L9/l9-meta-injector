# v4.0.0 Tag and Release Plan

> Status: **PLANNED — do not execute yet.** The repository is not ready for the
> Git-lifecycle steps below. This document records the plan; tagging, releasing,
> and recording resolution are separately authorized actions.

## Context

The v4.0.0 release candidate is merged to `main` (PR #44 hardening + PR #45 release).
`docs/release/v4.0.0-release-plan.json` declares the tag `v4.0.0` but holds the GitHub
release at `blocked_pending_exact_checkout_and_authorization` with `mutable_refs_forbidden`,
because at pack-authoring time the final commit SHA did not exist and no lifecycle
authorization was given. An exact final commit now exists on `main`; this plan cuts the
immutable tag, publishes the release, and reconciles the release SSOT — once the repo is ready.

### Ground truth
- `main` HEAD = `651430cff4dc6760b623debd1bcefb244be7a189` (merge of #45; carries v4.0.0).
- No existing tags; no existing GitHub releases.
- `npm run validate` (incl. `check:release-candidate`) and `npm run lint` pass on this state.
- No workflow triggers on `tags:`/`release:` — the tag and release are **manual** steps
  (`.github/workflows/*.yml` fire only on `push`/PR/`workflow_dispatch`).
- `scripts/check-release-candidate.js` enforces release identity and passes.

## Objective

Cut an immutable, annotated `v4.0.0` tag on the exact final `main` commit, publish the
GitHub release, then record the resolved SHA and authorization in the release SSOT.
**Success:** `v4.0.0` → `651430c…`, GitHub release published (latest, non-prerelease) with
CHANGELOG notes, and `docs/release/v4.0.0-release-plan.json` reflects `released`.

## Scope

**In**
- Annotated Git tag `v4.0.0` on `651430cff4dc6760b623debd1bcefb244be7a189` (exact 40-char SHA).
- GitHub release for `v4.0.0` with notes from the CHANGELOG v4.0.0 section.
- Follow-up PR recording the resolution in `docs/release/v4.0.0-release-plan.json`.

**Out**
- `npm publish` — fail-closed. `docs/package-publication-decision.json` is
  `blocked_pending_history_check` (5 unverified evidence items); `prepublishOnly` guards it.
- l9-deploy consumer migration — separate repo/task, unblocked by this tag but not part of this plan.
- Tagging any mutable ref (branch/`HEAD`/moving pointer) — forbidden by the release plan.
- SonarCloud remediation (new-code reliability D) — tracked separately; not a release gate.

```
1 (verify) → 2 (tag) → 3 (github release) → 4 (record resolution PR)
```

after Task 2 (immutable SHA exists) — separate plan.

## Risks

| Risk | Mitigation |
|------|------------|
| Tag points at a mutable/wrong ref | Tag the literal `651430cff4dc6760b623debd1bcefb244be7a189`; confirm `git rev-list -n1 v4.0.0` equals it |
| Accidental npm publish | Never run `npm publish`; `prepublishOnly` runs fail-closed `check:publication` |
| Release notes drift | Generate body from the committed `CHANGELOG.md` v4.0.0 section; identity re-checked by `check:release-candidate` |
| Recording on protected `main` | Do it via a PR (Task 4), not a direct push |
| Lightweight tag | Use an **annotated** tag so it carries authorship + message |
