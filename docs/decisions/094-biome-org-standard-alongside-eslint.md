# ADR-094: Adopt the Core-locked Biome contract alongside ESLint

## Status

Proposed

## Date

2026-11-11

## Context

The organization workflow `Organization CI (Core) / Analyze (central Core)` runs Biome only when the repository root holds `biome.json` or `biome.jsonc`. It installs Core's digest-locked Biome binary and runs `biome ci --reporter=github .` from the repository root in blocking mode. Cursor-Governance ci-parity applies the same `requires_any_file` condition. Until now this repository had no root Biome configuration, so neither surface checked formatting or Biome lint.

The operator decided that this repository adopts the full organization standard: formatter, `organizeImports`, and the recommended linter all enabled. ESLint stays the repository's own lint authority through `npm run lint`. The repository's product kind (`dependency`) and `.l9/meta-authority.yaml` do not change.

Core owns the consumer contract. `Quantum-L9/l9-ci-core` `presets/typescript/biome.json` is the locked Biome 2.5.8 configuration (the `biome` key of `.github/actions/install-consumer-ci/toolchain-lock.json`). Its README says to stamp the file rather than hand-author it, to append path excludes to `files.includes`, and not to rewrite the `formatter`, `linter`, `javascript` or `json` blocks.

The existing source does not follow one consistent formatter style. Measured against Biome line widths of 80, 100, 120 and 140, every width rewrites more than 100 `src/` files. No formatter setting reproduces the current layout.

## Options Considered

### Option A: Stamp the locked contract and format the tree once

- Pros: matches the organization standard exactly. Core and ci-parity check the same bytes. Later edits stay small.
- Cons: one large formatting diff across `src/`, `tests/`, `scripts/` and `dist/`, which conflicts textually with open branches that touch the same files.

### Option B: Hand-tune the formatter to the current style

- Pros: smaller diff.
- Cons: Core forbids rewriting the locked formatter blocks, and no setting matches the current layout anyway.

### Option C: Turn the formatter off for source directories

- Pros: no source rewrite.
- Cons: disables the formatter lane the operator chose. Rejected.

## Decision

We choose **Option A**.

1. `biome.json`, `.biomeignore` and `.editorconfig` are copied byte for byte from Core `presets/typescript/` (Biome 2.5.8). Only two kinds of repository-owned additions are made, both outside the locked blocks.
2. Excludes appended to `files.includes`:
   - `package.json`: npm rewrites it with its own serializer on every install.
   - `fixtures` and `examples`: test inputs and shipped samples whose bytes the tests and selfpack baseline depend on. ESLint ignores them too.
   - `reports`: dated audit evidence.
   - `docs/**/*.json`: generated evidence (`topology-conformance.json`) and machine-validated contracts.
   - `scripts/selfpack.baseline.json`: generated by `selfpack:update`.
3. Scoped `overrides` entries:
   - `lint/suspicious/noControlCharactersInRegex` is off in the nine files that deliberately match control characters: `src/frontmatter_patch.ts`, `src/glob.ts`, `src/metadata_index.ts`, `src/mutation_policy.ts`, `src/namespace.ts`, `src/operation_contracts.ts`, `src/yaml_serialize.ts`, `tests/carrier_value_safety.test.ts` and `tests/pdf_decoder.test.ts`. They detect or refuse hidden control characters, which is the behaviour under test.
   - `lint/correctness/noUnsafeFinally` is off in `src/check.ts`. The read-only check throws `CHECK_MUTATION_DETECTED` from `finally` on purpose, so a detected repository mutation overrides any result or error.
4. The tree is formatted once with the locked formatter, and `organizeImports` is applied. No other lint autofix is applied.
5. The remaining recommended-rule errors are fixed in the code:
   - `forEach` callbacks that returned a value now use block bodies.
   - Two unsafe optional chains in tests now read `?.owner`.
   - A `void` function no longer returns a value.
   - `exec` assignment loops in `scripts/lib/public-api.js` now use `matchAll`.
   - Two implicit-`any` `let` declarations are typed.
   - `tests/archives_local_files.test.ts` imported `treeSnapshot` and also declared a local function with the same name. The duplicate import is removed, so the file uses its own snapshot oracle.
6. `dist/` is rebuilt from the formatted source. Nothing else is re-bound: the architecture manifest is computed in memory and the validation report is not committed (ADR-093).
7. No `@biomejs/biome` devDependency is added. Core supplies the binary. Local verification is `npx --yes @biomejs/biome@2.5.8 ci .`.

### Delivery

The change lands as five pull requests, so the hand-written code is reviewed apart from the mechanical churn:

1. #154: the 25 lint fixes above, in each file's existing style, with no formatting. This is the only hand-written code.
2. #155, #156 and #157: the format and `organizeImports` pass for `scripts/` and `schemas/`, `tests/`, and `src/` with its `dist/` rebuild. Each is mechanical: re-running the two Biome commands on it is a no-op.
3. This change: `biome.json`, `.biomeignore`, `.editorconfig` and the documentation. It merges last, because Core's Biome step turns blocking as soon as `biome.json` is on `main`.

ESLint is unchanged and stays the repository's own lint authority. Biome warnings and infos do not fail `biome ci`. Only errors fail it.

## Consequences

- `biome ci .` passes on this tree, and Core's blocking Biome step becomes active for this repository once this change lands.
- Open branches that touch formatted files will conflict textually. Do not resolve the conflict by hand. Re-run the formatter on the merged result: `npx --yes @biomejs/biome@2.5.8 check --write --only=assist/source/organizeImports .`, then `format --write .`. Then rebuild `dist/`. The formatting is mechanical, so re-deriving it is exact.
- When Core moves the Biome version, the `$schema` here must follow, either by re-stamping or by editing that one key.
- New files must be Biome-formatted before they are committed. New control-character regexes outside the listed files need a fix or an explicit addition to the override.
