# Universal tracked metadata v2: operation, migration and rollback

This is an explicit producer candidate contract, not an automatically deployed fleet policy. ADR-081 records technical approval; release and each consumer's adoption remain separate.

## What the producer proves

`runTrackedCoverage` on the experimental `l9-meta-injector/advanced` surface takes a portable `repositoryId`, local Git root, explicit `revision`, `contract: "l9.tracked-carrier-policy/v2"`, and `producerVersion`. It resolves an immutable commit/tree once and returns `TrackedMetadataCompilation`: canonical v2 index bytes and SHA-256, current records, one disposition per tracked leaf, and a complementary external coverage receipt. The SHA-256 measures the generated index bytes, not a subject content digest.

The census population includes hidden files, symlink blobs, gitlinks, binary/archive names, generated files and force-tracked ignored files. It excludes working-directory noise and remote submodule contents. Protected self-index/root-manifest, secret and unsupported representation outcomes remain accounted. The closure equation is **indexed + protected + unsupported = tracked tree leaves**, with exact identity and Git evidence equality. Index headers and historical migration claims are not additional current entries.

The default census does not inspect subject payloads. `content_hash` is null, its scope is `not_inspected`, semantic type/content kind remain Unknown, and host materializability is not assessed. Filename hints are not payload detection; an extensionless LFS pointer or binary remains Unknown. Git object IDs identify Git objects and are never substituted for measured content SHA-256.

## Versioned storage and identity

The one active store is `.l9/metadata-index.jsonl`. V2 always begins with a canonical header, even with zero records. Homogeneous v1/v2 dispatch is available through `readVersionedMetadataIndex`; old `parseMetadataIndex` remains v1-only and refuses v2. Unknown/mixed/noncanonical stores fail closed. The header and current records never embed the identity of a hypothetical final commit that contains their own newly generated bytes.

Canonical IDs use a reversible `l9.path/v2:` repository/path-byte tuple. Case, punctuation, Unicode normalization and raw bytes do not collapse. A record's `legacy_alias` is only a deterministic old-algorithm projection; it is not proof of the ID previously consumed by a deployment.

## Migration ceremony

1. Verify and retain the immutable producer candidate/release provenance independently. Before production writes, pass the repository's intended writer revision as `--writer-ref`/`expectedWriterRef`; this compares its declared binding and does not by itself attest the installed code's origin.
2. Keep the existing authority as the sole repository binding. Check/apply require canonical producer authority and independent legacy-writer inspection. Do not introduce per-repository carrier logic or a second metadata writer.
3. Archive the original v1 index outside the source tree for backout. Adapt consumers to the explicit v2 reader and minimal Git-fact records before choosing migration; v2 is not a drop-in flat v1 metadata/header schema.
4. Run `tracked-check` first. Without `--migrate-v1`, a present v1 store is a version conflict, not permission to replace it. Migration requires explicit boolean consent; check never writes.
5. Run `tracked-apply --migrate-v1` only at the intended current commit and with unchanged tracked sources. The operation commits only the index through the existing compare-and-swap transaction.
6. Verify the succeeding `tracked-check` and a second unchanged `tracked-apply`. Both must use the same source revision/producer version; the second apply performs zero index writes.

On consented migration, `legacy_identity_claims` inside the same v2 header retains the observed v1 index SHA, migration-time snapshot, exact old paths, actual custom/bound or JSON-valued ID claims, absent-ID states and legacy content-hash claims. These are historical and `legacy_v1_claim_not_revalidated`, never measured current-content proof or current canonical keys. Retired/protected old paths remain history, not extra current metadata entries. A v2 replay carries the history unchanged. External `migrationEvidence` additionally binds the final target index hash; that target hash is deliberately absent from the header to avoid self-reference.

## Mutation and currentness boundary

The tracked v2 seam is index-only. It creates no source/Markdown/header/sidecar intents. Existing valid legacy v1 annotation behavior is retained, but legacy writers refuse to implicitly downgrade an active v2 store. Standalone annotating inventory is not an alternate dispatch into this governed workflow.

Coverage can inspect historical snapshots or bare object stores without a checkout. Check/apply require a working tree at the requested current HEAD. They inspect authority/control data and the active index and therefore are **not** the content-free census operation. Apply validates currentness before commit and while rollback backups remain available, rejects stale/staged/unsafe sources and metadata destinations, and preserves index CAS. Pending transaction state is held for the existing explicit recovery workflow instead of silently running source-mutating recovery from this seam.

Currentness is a fail-closed repeated observation, not a global filesystem lock. Assume-unchanged/skip-worktree flags and unsafe source ancestry hold. An initialized gitlink checkout holds rather than opening the submodule to verify its HEAD. Locally configured Git filter programs require a separate trusted currentness proof; this seam does not execute them. Git configuration includes are unsupported by the strict content-free observer; use an isolated bare snapshot whose Git control configuration does not include subject files. Neither limitation drops rows from a successful snapshot receipt or claims an incomplete census is complete.

## CLI and external exports

Use the installed bin's explicit `tracked-coverage`, `tracked-check` and `tracked-apply` prefixes. Legacy Action modes are unchanged. Roots remain relative to and contained within the current workspace. `--repository` and `--revision` are required; unknown/duplicate/legacy mutation flags and invalid numeric limits fail before an operation.

Without `--out`, results remain in memory and the CLI prints its own numeric summary. An export parent must already exist, the destination must be a new filename outside the source repository, and symlink/noncanonical ancestry is refused. Descriptor-anchored no-replace export uses Linux `/proc/self/fd`; unsupported export platforms fail before file creation and can use the portable in-memory API. Temporary and raced output cleanup is limited to the export's own inode. Private path-level receipts belong only in an authorized private location, never in a public producer PR.

External report writing is not a source carrier transaction. Input placement errors are rejected before apply; a later output/resource failure is reported separately and must not hide a successful canonical-index commit in the numeric summary. Check/apply export wrappers identify authority inspection as performed; their nested coverage is the census projection, not a claim that the entire operation read no control contents.

## Backout and release boundary

Pin the prior validated producer and explicitly restore the archived v1 index bytes through the repository's approved rollback procedure. A legacy writer will not silently overwrite v2; do not bypass that refusal with standalone inventory. No source bodies were changed by the tracked seam. Remove/replace only the active index under explicit rollback authorization, not repository artifacts or aliases to suppress collisions.

The producer candidate does not merge or modify Topology PR #35, override its manual/no-CI refresh decision, deploy freshness automation or opt in any other consumer. Snapshot receipts prove the named input revision only. Package release, maintained tag movement, npm publication, consumer adoption and recurring checks remain separately authorized.
